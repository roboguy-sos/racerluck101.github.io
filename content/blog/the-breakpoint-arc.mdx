### Hardware breakpoint vs Software breakpoint

![test](/blog/the-breakpoint-arc/hard-vs-soft-breakpoints.png)
#### Hardware breakpoint
- use Dr0-3 registers to store the address where we want to stop execution flow with cordination of Dr7
![Dr7.png](/blog/the-breakpoint-arc/dr7.png)
- G0–G3 flags = 1 → the corresponding hardware breakpoint (Dr0–Dr3) is enabled.
- This could be helpful for if you want to debug memory corruptions.
![Screenshot](/blog/the-breakpoint-arc/debuggin-registers.png)
#### Software breakpoint
- uses INT3 opcode 0xCC to hit breakpoint then reach back the orignal instruction and restore it.
for example:
```asm
step 1
rsi -> mov rax, rbx 
       call <printf> 
step 2 
rsi -> cc rax, rbx  ; When executed it calls the debugger’s exception handler.
       call <printf>;

rsi -> 48 89 D8   ; target .text, original
       call <printf>
---------------------------------------
; debugger reads 0x48 into bp.originalByte, writes 0xCC:

rsi -> CC 89 D8   ; target .text, patched
       call <printf>
; bp.originalByte == 0x48  (debugger memory)

; breakpoint hits, debugger restores:

rsi -> 48 89 D8   ; target .text, restored from bp.originalByte
       call <printf>
```
- software breakpoints actually change the Cyclic redundancy check.

# Hardware Breakpoints Algorithm

- how code is being execute 
```c
opcodes  ->  thread  ->  stack-unwind  ->  registers
   |            |             |               |
 .text      RIP/fetch      frame walk      Dr0-7, EFLAGS

```
*means breakpoints are specific to thread not global*
- Since hardware breakpoints must be saved in one of the Dr0-3 registers, each thread can install a maximum of 4 hardware breakpoints at the same time.
- we need to use get and set the thread context using `GetThreadContext` and `SetThreadContext`
- EXCEPTION_SINGLE_STEP
A trace trap or other single-instruction mechanism signaled that one instruction has been executed. exception will be handled using a Vectored Exception Handler which is set using `AddVectoredExceptionHandler` and `RemoveVectoredExceptionHandler`
